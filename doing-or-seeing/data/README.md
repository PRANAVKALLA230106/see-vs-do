# Dataset: Seeing vs Doing causal stories (Team Ground Truth, ADA Jackfruit)

We built this dataset ourselves. It is synthetic, generated by the scripts in `data_generators/`. It contains no personal data and no scraped text.

Each item is a short story in which one **fact** is stated in different ways. We use it to measure whether a language model treats a fact as something it **observed** (seeing) or as something **imposed from outside** (doing, Pearl's do()), and then whether an **activation patch** of that fact behaves like seeing or like doing.

## Size

| Structure | Scenarios | Variants per scenario | Rows | File |
|---|---|---|---|---|
| Chain A → B → C | 45 (20 exploration + 25 confirmation, written after the analysis was fixed) | 24 | 1,080 | `main_patching_data/pairs_chain.csv` |
| Collider A → C ← B | 19 | 24 | 456 | `main_patching_data/pairs_collider.csv` |
| Fork B ← A → C | 15 | 24 | 360 | `main_patching_data/pairs_fork.csv` |
| **Total** | **79** | | **1,896** | |

The 24 variants of a scenario come from 6 opening lines × 4 character names. Variants 16–23 are held out for every score. Variants 0–15 were used only to learn steering directions, and later as fresh items for the pre-registered DS2 test.

## One example row (chain `ch_ice_bus`, variant 0)

| Column | Text |
|---|---|
| `base` (neutral, patch target) | This happened last year. Tom was waiting for the school bus early in the morning. The road was **long**. |
| `see` (fact stated) | … The road was **icy**. |
| `false` (fact negated) | … The road was **dry**. |
| `do` (fact imposed) | … A broken water pipe had flooded the road overnight and the water froze, so the road was **icy**. |
| `q_cause` | Did it snow during the night? |
| `q_eff` | Was the bus late? |
| `q_med` | Was the road icy? |

The cause (snow) never appears in any story. It is only asked about.

## Columns

- `set`: exploration / confirmation (chains only).
- `scenario_id`: prefixed `ch_` (chain), `cf_` (confirmation chain), `co_` (collider) or `fk_` (fork).
- `item_id`, `variant`, `name`, `opener`: which of the 24 surface variants this row is.
- `see`, `false`, `base`, `do`: the four versions of the story.
  - Colliders add `see_A` (C and the other cause A both stated) and `A_only` (A stated, C neutral). These are used to measure explaining away.
- `span_*`: character span of the fact sentence in that version.
- `wspan_*`: character span of the key word (the token that is patched).
- `q_cause`, `q_eff`, `q_med`: Yes/No probe questions for the cause, the effect and the fact itself.
  - Colliders use `q_b`, `q_a` and `q_c`.
  - Forks: `q_eff` is the sibling effect.

Three unrelated **filler** questions are added in code to measure the model's general drift towards "Yes": "Was there a cat nearby?", "Did someone in the story have a brother?" and "Was a radio playing?".

## Other folders

- `earlier_steering_data/` holds the stories used for the first, steering-based experiments: one row per surface variant, with cause sentences for learning directions.
  - `stories_collider24.csv` is the 24-variant collider set.
- `pilot/pilot_stories.csv` holds the 20 hand-written pilot stories (Days 1–3) that we used to choose the model. They are excluded from all evaluation.

## Validity filters

Edits are scored only on scenarios where the model itself separates seeing from doing in text. The rules were fixed before any edit was scored:
- Δcause(see) > 0.5
- Δeffect(see) > 0.5
- Δeffect(do) > 0.5
- r_see − r_do > 0.25

The models' results on these filters are recorded in `results/*/…reference_scenarios.csv`.

| Model | Chains passing |
|---|---|
| Qwen3-4B-Base | 30 of 45 |
| Llama-3.2-3B | 23 of 45 |
| Gemma-2-2B | 12 of 45 |

## Regenerating

Run the generators from `data_generators/`; they are deterministic:

```
python make_pairs.py
python make_pairs_collider.py
python make_pairs_fork.py
```

The Kaggle notebooks embed these CSVs, gzip+base64, so that they run without Drive.
